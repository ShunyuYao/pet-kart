# 漂移积能与 N₂O 氮气加速（0.7.0）

## 授权和依赖

2026-10-15 用户追加漂移积能、满格主动氮气加速需求，继续此前“没有新设计，沿用现有风格制作”的授权。基于赛车独立仓库 `codex/terrain-playground` 的 `bd36d47`，保留五图机关与滑翔。源码、专用测试与产物均归 `ShunyuYao/pet-kart`。不修改宿主 SDK 或公开类型/脚手架/市场，因此三个公开仓无需同步；不安装、发布或合并。

参考机制：[Nexon 游戏总监在 PlayStation Blog 的 KartRider: Drift 介绍](https://blog.playstation.com/2021/10/27/kartrider-drift-speeds-to-ps4-in-2022/)：成功漂移积攒 boost gauge，满后主动激活。下列数值是本游戏自己的调校，不宣称复制原作。无需新增外部素材、第三方库或接口。

## 行为

- 一管 100 点，每秒有效漂移 +30，约 3.34 秒累计充满；短漂移之间保留，不额外囤积。
- 前进速度 >11 m/s、有转向的地面漂移、在路面且未擦墙/受击、实际前向进度足够才积能。空中、越野、原地、氮气加速期间不积能。
- N、左右 Ctrl、手柄 L3 或可聚焦仪表按钮释放；满管才消耗，3 秒，平路速度上限 45 m/s（162 km/h）。坡度继续影响车速。
- 氮气独立计时，保留漂移小涡轮、蘑菇、加速带的原规则，但速度与时长不相加。受击中断已使用的氮气，未使用能量保留。
- 提前按、长按、网络重复/乱序都不排队自动释放、不重复消费；比赛外与冲线后不能释放或积能。每次新比赛重置。
- 仪表始终区分积能百分比、满格就绪、正在加速的剩余时间；青蓝长尾焰、同色粒子、音效和镜头视野反馈。主键与手柄说明在仪表中可见。
- 房主权威，客端共享同一规则预测，意图带单调计数；收到确认后收敛。互动协议 v4，宿主 SDK 声明仍为 v2，老版不混局。
- 电脑继续现有驾驶策略；本轮没有给电脑免费能量或隐形加速，也没有改动其难度策略。

- 新增测试保护“按早自动释放”“一管重复使用”“只显示能量却不能真的加速”“联机漏传按钮”“重赛保留旧能量”等具体故障。物理单测允许直接构造边界；真实 E2E 只读观察状态、真实 CDP 按键积能和释放，不注入能量或缩短计时。

## 发现与处理

- 实现前由 Agent 检查发现：网络适配器显式筛选输入字段，单改模拟层会让客人的新按键静默丢失。同步扩展意图和快照，并在实际三宿主 E2E 断言客端释放、房主接受与远端尾焰。
- 第一轮新增的 4 个规则测试先失败（缺少功能，保留本轮工具输出），实现后全部通过。
- 第一轮真实按键测试（`artifacts/nitro-e2e/2026-10-15T03-47-57-578Z`）失败：原自动驾驶只做最小幅度循迹，整场很少触发漂移，未充满氮气。这是测试场景不足；保留失败报告，改为在合法路宽内交替走线与转向漂移，不注入状态、不降低充能门槛。再次验证完整路径。

- 第二轮专项已实际释放两管，但测试把第二管的累计次数误算进“第一管长按”断言（`2026-10-15T03-49-38-927Z`）。修正观察区间，未改产品逻辑；第三轮 12 项全部通过。后续计数断言固定区分一次操作与整场累计。

- 相邻浏览器回归发现既有颁奖断言的采样时序问题：4.6 秒读取动画状态后先等待高分辨率截图，再检查结果面板，可能已经跨过 8.2 秒自然结束边界。保留 `artifacts/browser-e2e-nitro-first-failure`；改为同一 CDP 求值原子读取动画时间和面板隐藏状态，仍严格要求动画中段且面板隐藏，不放宽产品门槛。后续长测试串行执行，避免同时多个 3D 实例争用截图资源。

图形颜色诊断接口核对了 [Three.js r164 官方 Color 文档](https://github.com/mrdoob/three.js/blob/r164/docs/api/en/math/Color.html)；本会话 Context7 工具不可用，采用匹配仓库版本的官方文档。
